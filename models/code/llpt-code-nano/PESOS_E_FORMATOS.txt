LLPT CODE NANO (1B) - ESPECIFICAÇÃO DE PESOS, ESTRUTURA E FORMATOS SUPORTADOS
===============================================================================

1. ESTRUTURA DE DIRETÓRIOS PARA PESOS E CHECKPOINTS
-------------------------------------------------------------------------------
O modelo LLPT Code Nano organiza seus pesos e checkpoints no seguinte fluxo:

  models/code/llpt-code-nano/
  ├── weights/
  │   ├── raw/           -> Pesos originais sem quantização / pré-treino (BF16 / FP16)
  │   │   ├── model.safetensors (ou pytorch_model.bin)
  │   │   ├── config.json
  │   │   └── tokenizer.json
  │   ├── checkpoints/   -> Checkpoints salvos durante o treinamento (checkpoint-epoch-X/)
  │   │   ├── checkpoint-epoch-1/
  │   │   └── checkpoint-epoch-2/
  │   ├── final/         -> Modelo final consolidado pós-treinamento
  │   │   ├── pytorch_model.bin
  │   │   ├── config.json
  │   │   └── tokenizer_config.json
  │   └── gguf/          -> Pesos quantizados para execução rápida (llama.cpp / Mobile)
  │       ├── llpt-code-nano-f16.gguf
  │       ├── llpt-code-nano-q8_0.gguf
  │       └── llpt-code-nano-q4_k_m.gguf
  └── dataset/           -> Conjuntos de dados em formato .txt reorganizados por finalidade
      ├── Programação/
      │   ├── python.txt
      │   ├── javascript.txt
      │   ├── ...
      │   └── fim_examples.txt
      └── Conversação/
          └── documentation.txt

-------------------------------------------------------------------------------
2. DIFERENÇA ENTRE PESOS INICIALIZADOS E PESOS TREINADOS
-------------------------------------------------------------------------------
  - Pesos Inicializados (Aleatórios):
    Criados durante a inicialização da arquitetura neural `LlamaForCausalLM` com base nas
    dimensões de `config.json`. Úteis para iniciar um novo pré-treino do zero ou rodar testes de pipeline.
    Geram tokens aleatórios caso utilizados diretamente em inferência.

  - Pesos Treinados:
    Resultantes da execução do processo de otimização (`train.py`) com backpropagation e otimizador
    AdamW sobre datasets .txt.
    Salvos automaticamente em `weights/checkpoints/` e `weights/checkpoints/final/`.

  - Armazenamento no Git:
    Arquivos de pesos (.bin / .safetensors / .gguf > 50MB) não devem ser commitados no repositório Git.
    Armazene-os separadamente em local de armazenamento externo ou Hugging Face Hub e carregue-os via `--model_dir`.

-------------------------------------------------------------------------------
3. FORMATOS E PRECISÕES DE PESOS
-------------------------------------------------------------------------------

A. FORMATO PYTORCH / SAFETENSORS (.bin / .safetensors)
   - Descrição: Formato padrão PyTorch e Hugging Face.
   - Localização: weights/checkpoints/ final/
   - Tamanho estimado modelo 1B: ~2.0 GB em FP16 / BF16.

B. FORMATO GGUF (.gguf)
   - Descrição: Formato unificado do llama.cpp para inferência ultraeficiente CPU/GPU.
   - Localização: weights/gguf/
   - Variantes:
     * Q4_K_M (Quantização 4-bits): ~0.7 GB VRAM/RAM (Ideal para Mobile e Termux).
     * Q8_0 (Quantização 8-bits): ~1.1 GB VRAM/RAM (Ideal para Desktop).

-------------------------------------------------------------------------------
4. REQUISITOS DE HARDWARE E LIMITAÇÕES
-------------------------------------------------------------------------------
  - Treinamento completo (1B Parâmetros):
    * VRAM/RAM mínima para batch_size=2: ~6GB RAM/VRAM.
  - Treinamento em dispositivos Mobile / Termux:
    * Recomendado batch_size=1, max_length=128-256 e poucas épocas em CPU.
